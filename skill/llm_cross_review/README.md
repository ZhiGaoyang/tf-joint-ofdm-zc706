# llm_cross_review：独立只读交叉审查 → 逐条复现 → 先红后绿 → 书面答复

类型：协作流程 + 文档模板。

## 适用场景

由一个大模型（或一个人）完成的 RTL、脚本、实验流程，在上板或交付前请另一个独立审查者（另一个模型或另一位成员）把关。与 OFDM 题目无关。

## 来源

本项目创新扩展（子载波组屏蔽）的 RTL 与 PS 脚本由一个模型实现并自测通过后，请独立审查者做了一轮只读审查，提出 11 项问题；实现方逐条复现确认（11 项全部成立），修复后重新仿真、综合与实现，再请审查者复审；第一次复审新提出 4 项（2 中 2 低），第二次复审新提出 3 项（均低），第三次复审新提出 1 项（低，评估后列为已知限制），逐项处理。记录：`report/review/` 下四轮的说明、报告与逐条答复（`round1_*`–`round4_*`）。

在此之前实现方自己的测试已全部通过，但审查仍发现了自测没有覆盖的问题，例如：读超时后旧响应被下一次读取接走、清零与计数同拍时计数残留、诊断寄存器位域错位、策略在某些返回路径上选出非法帧长、板上命令记录的是 `tail` 的退出码、重复部署会覆盖回滚备份、测试检查器放行不完整的成功记录。

## 用法

1. **写审查说明**（实现方）：背景与必读文档、审查对象清单（文件、SHA、改动行数、只看改动的对比命令）、按模块列出的具体问题、已知并已接受的限制（避免重复报告）、可运行的检查命令、输出格式。
2. **只读审查**（审查方）：不改任何源文件，只写一份结果文件；探针和日志写到独立目录；每条注明严重程度、`文件:行号`、触发条件、依据，并区分"实际复现""代码推理""覆盖缺口"；最后列出"审查过未发现问题"和"没审查到"的部分。
3. **逐条处理**（实现方）：不照单全收。每条先复现（定向仿真、主机测试或明确的推理），写出在修复前失败的测试，修复后转绿；有异议的保留反证。修复后在最终源码上重跑受影响的回归，并核对运行前后源文件哈希不变。
4. **书面答复**：每条的结论、复现证据、修复、验证，加上覆盖缺口的处理与仍未覆盖的部分。
5. **复审**：请审查方判定每条"已解决 / 部分解决 / 未解决"，并检查修复本身是否引入新问题。

## 已验证效果

- 11 项中有 3 项是 RTL 问题，修复前均由定向测试复现失败（例如超时后第二次读拿到第一次地址的数据 65533），修复后通过；最终源码的 RX 11/11、环回 6/6、开发核心仿真通过，整平台实现时序收敛（`docs/innovation/stage1_nc_rtl_report.md` 第 7 节）。
- 审查与修复都在上板之前完成，没有占用板上调试时间。

## 失效条件与边界

- 审查方与实现方共享同一套模型、向量和参考实现时，审查不能替代独立的形式验证；本项目审查方也明确说明其算术转录"不是 RTL 穷举证明"。
- 审查结论受审查说明的范围限制；没列进说明的文件可能没被看到，所以必须要求审查方写"没审查到的部分"。
- 只在一个项目、一轮审查加三轮复审上实践过。
