# format_change_regression：帧格式改动后的端到端回归与"隐含标定"检查

类型：检查清单 + 踩坑记录。

## 适用场景

在已验收的收发系统上改帧格式（载波分配、帧头字段、填充方式、导频等），而同步、检测、均衡等模块不改的任何题目。与具体调制方式无关。

## 现象与来源

| 现象 | 本项目中的实际记录 |
|---|---|
| 只改了帧头的载波分配（屏蔽部分子载波组），已验收的检测器没有任何改动，长 16QAM 帧却出现误码 | `build/ofdm_nc/rxs_run02` 的 nc_lmax：屏蔽 3 组的 4096 B 16QAM 帧 CRC 失败，EVM 14.7%（同条件不屏蔽为 3.6%） |
| 同一帧在帧间留空、干净信道下正常，说明不是屏蔽逻辑本身的错误 | 诊断场景 `build/ofdm_nc/rxs_dbg01`：全部正确 |
| 根因：检测器的定时常数是在旧帧格式上标定的；旧帧头里 24 个常数填充子载波形成固定的时域结构，屏蔽后填充减少，平台区中心偏晚，最多约 14 个样本，超过 CP 内回退量 | 模型复现 `build/stage1_nc/timing_by_mask.py`、`timing_cause.py`：偏差与填充子载波数一一对应（24 个 → 0.3，16 个 → 1.4–3.2，8 个 → 4.5–7.7，0 个 → 7.0–11.2 个样本） |

## 用法

1. 改格式前，列出所有"在旧格式上标定过的常数"：定时偏置、门限、窗口回退、AGC 目标、归一化系数等。逐项写明它是用什么数据标定的。
2. 格式改动后，必须在**端到端**仿真中用真实的检测、FFT、均衡模块跑一遍，覆盖新格式的所有极端取值（本项目是屏蔽 0–3 组、最长帧、帧间无间隔）。只做模块级测试发现不了这类问题。
3. 统计"中间量"的分布，而不只是看最终是否误码：本项目先发现的是"检测起点相对真实起点的偏差"随掩码系统性变化，再定位原因。
4. 用模型在无噪声条件下复现偏差，并做对照实验（改一个变量），确认根因后再决定是改常数还是改格式。
5. 修复优先选"不改已验收模块"的方案（本项目把 CP 内回退量从 10 改为 16，是寄存器配置），并写明代价（多径容限由约 16 个样本降到约 10 个样本）。

## 已验证效果

- 回退量改为 16 后，最终源码的 RX 回归 11/11 场景通过（包括原格式的 6 个回归场景），TX→RX 环回 6/6 通过；见 `docs/innovation/stage1_nc_rtl_report.md` 第 4 节与第 7 节。

## 失效条件与边界

- 只在本项目的平台区定时检测器上验证过；匹配滤波、互相关峰值等其他定时方法的敏感量不同，需要重新找"隐含标定"。
- 本项目的修复依赖 CP 足够长（32 个样本）；CP 很短的系统没有余量调整回退量，只能改检测器或改格式。
- 结论来自有线信道和仿真，没有在空口多径信道上验证。
